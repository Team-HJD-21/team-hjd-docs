# Player 검증과 제한 사항

**기준:** main `6b4310dc` (#549, 2026-10-24) · **영역:** 이영빈 · **현재 원본 경로:** `Assets/Scripts/Features/Player/`, `Assets/Scripts/Core/Presentation/Scene/PlayerSceneAdapter.cs`.

## 연결 검증

- MainCamera 태그·활성 카메라와 Rigidbody2D가 준비됐는지 확인합니다.
- Q/Tab과 GameInput의 입력 경로를 따로 확인합니다.
- EnemyHealth와 Monster에 중복 피해를 주지 않는지 확인합니다. Client의 EnemyHealth 피해 호출은 무시됩니다.
- HP 표시가 반복 이벤트에도 안정적인지 확인합니다. 사망 시 `onDeath`가 한 번 호출되는지와 입력 차단·이동 중지가 적용되는지도 확인합니다.
- 선택된 Q/E 스킬의 쿨타임과 CanPrepare / CanUse / CanRecover, 선택창·조작 차단에 따른 제한을 확인합니다.
- Player V2 상태가 Core PlayerState와 자동 동기화된다고 가정하지 않습니다.

검증 절차 안내이며 실제 Unity 플레이 테스트를 수행했다는 의미가 아닙니다. Initial HUD의 냉각·활성화·강화 제한 확인 항목은 [UI 연동 안내](ui-integration.md)를 참고하세요.

## #549 무기·설치·HUD 회귀 확인

- Tab의 세 무기 순환과 스패너 미연결 시 두 무기 폴백, 8방향 표시와 연속 탄환 조준의 차이를 확인합니다.
- 공격 중 방향·정지/이동 전환이 진행률·예약 판정을 재시작하지 않는지 확인합니다.
- 스패너의 전방·후방·벽 뒤·다중 Collider 적, 예약 중 무기 전환·비활성화·조작 차단과 Animator 복원을 확인합니다.
- 수리 모션이 적 공격을 함께 수행하지 않고 타격 때 대상을 재검사하는지 확인합니다. 일반 터렛의 회복 상한·이벤트·활성/냉각/전력 유지와 잠금·파괴·자동 활성화 중 거부를 확인하고 CU·임시 터렛은 제외합니다.
- 설치 진입·취소·불가 클릭의 수량/쿨타임 유지, 주변 8칸·각도 경계·먼 커서·Player 이동·정렬 Z를 확인합니다.
- 캐릭터·포탑 본체 겹침은 거부하고 Trigger·탄환은 제외하는지, 확정 직전 들어온 캐릭터도 재검사로 막는지 확인합니다. 성공은 한 번만 차감·생성하고 UI 클릭·일반 터렛 선택에 중복 적용되지 않아야 합니다.
- 선택창·다른 스킬·행동 불가·비활성화 때 미리보기가 정리되는지, F 회수가 Collider 표면 XY 거리 기준인지 확인합니다.
- 씬 HUD의 늦은 Player 연결, 원격·다른 씬·복수 불명확 Player 거부, 재연결·씬 재진입 후 구독/리스너/안내 정리와 Loadout 유지를 확인합니다.
- 필수 슬롯 누락 시 연결 거부, 보조 UI/아이콘 누락 시 정상 선택 유지, 닫힌 선택창을 열 때 최신 데이터 반영을 확인합니다.
- 먼 일반 터렛의 창·사거리 유지와 조작 차단, 접근 시 재클릭 없이 거리 안내 해제와 기존 잠금·냉각 제한 유지를 확인합니다.

이번 동기화는 공개 시그니처 정적 대조와 사이트 검사·빌드이며 Unity 컴파일·Test Runner·실제 플레이를 실행한 기록이 아닙니다. 원본의 테스트 코드 추가도 실행 통과를 뜻하지 않습니다. 기존 체력 동작의 기준은 [체력 문서](health.md)를 따릅니다.
